# Lesson Template and Teaching Method

## Teaching philosophy

A lesson should make a difficult concept feel approachable without making it inaccurate or superficial.

Use this learning sequence:

**Understand → Visualize → Experiment → Implement → Practice → Apply**

Not every lesson needs every media type. Choose the blocks that serve the learning objective.

## Standard lesson structure

### 1. Lesson introduction
- What are we learning?
- Why does it matter?
- Where is it used?
- What will the learner be able to do by the end?

### 2. Simple explanation
Explain the idea in plain English. Introduce jargon only when necessary and define it immediately.

### 3. Real-world analogy
Use a familiar analogy to establish intuition. State where the analogy stops being accurate so it does not create misconceptions.

### 4. Visual explanation
Use diagrams, animation or a step-by-step visual to show what is happening.

### 5. Interactive experiment
Let the learner change inputs or parameters and observe the consequences.

### 6. Technical explanation
Introduce correct terminology, architecture, equations and underlying mechanisms.

### 7. Practical implementation
Show a worked example. Include runnable code when appropriate, explain important lines and show expected output.

### 8. Guided practice
Give the learner a small task with hints and feedback.

### 9. Knowledge check
Use a short quiz or scenario. Test understanding, not only memorization.

### 10. Real-world application
Explain how the concept appears in an actual system or workflow.

### 11. Summary
Include:
- Key takeaways
- Important terms
- Visual recap
- Common misconceptions
- Further reading

### 12. Next step
Recommend the next lesson based on prerequisites and learning progression.

## Writing rules

- Prefer short paragraphs and descriptive headings.
- Explain one major idea at a time.
- Define acronyms on first use.
- Use examples before abstract generalizations when appropriate.
- Distinguish simplified teaching models from production systems.
- Never invent a capability or imply that a model is deterministic when it is not.
- Include equations only when they help the learner.
- Explain every symbol in an equation.
- Provide citations or links for claims that may change.
- Use diagrams that clarify relationships, not decorative illustrations.
- Make examples inclusive and relevant to different backgrounds.

## Difficulty progression

### Beginner
Focus on intuition, everyday examples and guided interaction. Keep prerequisites minimal.

### Intermediate
Introduce terminology, implementation details, trade-offs and independent exercises.

### Advanced
Cover architecture, mathematics, evaluation, edge cases, production constraints and design decisions.

A topic can have multiple lessons at different depths rather than forcing all learners through one long lesson.
